## Chapter 5: Reinforcement Learning for Robotics — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Define the four core RL components: agent, environment, reward, policy. | Agent = decision-maker; Environment = system it interacts with; Reward = scalar feedback signal; Policy = mapping from state to action. Exam tip: questions often test whether you can identify which robot component maps to which RL term. |
| 2 | What is 'reward hacking' and give a robotics example? | Agent maximizes the literal reward signal while failing the intended task (e.g., gripper hovers near object to maximize negative-distance reward instead of grasping). Exam tip: fix is adding explicit task-completion terms, not just reducing training time. |
| 3 | What guarantee does potential-based reward shaping provide? | It adds dense shaping reward derived from a potential function while provably NOT changing the optimal policy. Exam tip: distinguishes 'safe' shaping from arbitrary shaping that can introduce reward hacking. |
| 4 | What parameters are typically randomized in domain randomization for legged robots? | Friction, mass/inertia, motor strength/torque limits, sensor noise, and actuation latency. Exam tip: visual randomization (textures/lighting) is used for vision policies, not for closing a locomotion dynamics gap. |
| 5 | What is the 'sim-to-real gap' in robotics RL? | The performance drop when a policy trained in simulation is deployed on real hardware, caused by mismatched dynamics, contact models, sensor noise, and latency. Exam tip: mitigated via domain randomization, system identification, and residual learning — not by training longer in sim alone. |
| 6 | PPO vs SAC vs TD3 — key distinguishing property for exam purposes? | PPO = on-policy, stable but less sample-efficient. SAC = off-policy, replay buffer, entropy-regularized, sample-efficient for continuous control. TD3 = off-policy, deterministic, addresses overestimation bias in DDPG. Exam tip: 'off-policy + replay buffer + entropy' always points to SAC. |
| 7 | When does classical control (PID/MPC) outperform RL in robotics? | When dynamics are well-modeled, the task is structured, real-time/high-frequency control is needed, and formal stability/safety guarantees are required. Exam tip: RL is favored when dynamics are unknown/complex or the task is hard to specify analytically. |
| 8 | Model-based RL vs model-free RL — sample efficiency difference? | Model-based RL learns a dynamics model and uses it to generate synthetic rollouts/plan, requiring far fewer real-world interactions than model-free methods (e.g., PPO/SAC trained purely from real rollouts). Exam tip: pick model-based RL when real robot time is the limiting resource. |
| 9 | Why do GPU-parallel physics simulators (e.g., Isaac Gym) matter for robotics RL training? | They can run thousands of simulated environments in parallel on a single GPU, dramatically increasing the amount of simulated experience generated per wall-clock hour versus CPU-based or real-hardware rollouts. Exam tip: this is why most modern locomotion/manipulation RL policies are trained almost entirely in simulation. |
| 10 | What did OpenAI's Dactyl project demonstrate? | A robotic hand (Shadow Hand) trained entirely in simulation using domain randomization achieved in-hand manipulation (e.g., cube reorientation) on real hardware with no real-world fine-tuning. Exam tip: canonical case study for 'domain randomization enables zero-shot sim-to-real transfer.' |
| 11 | How do modern legged robots (e.g., ANYmal, MIT Mini Cheetah) commonly combine RL and classical control? | A hybrid architecture: MPC/classical control handles low-level, high-frequency stabilization and foot placement, while RL learns higher-level gait/behavior policies or residual corrections. Exam tip: pure end-to-end RL is less common in production legged systems than hybrid architectures. |
| 12 | What is the standard RL environment interaction loop (API-level)? | obs = env.reset(); loop: action = policy(obs); obs, reward, done, info = env.step(action). Exam tip: exam scenarios describing 'observation, action, reward, done' are testing recognition of this standard Gym-style interface. |
