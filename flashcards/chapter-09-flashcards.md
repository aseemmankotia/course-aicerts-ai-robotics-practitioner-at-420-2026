## Chapter 9: Robotic Process Automation (RPA) — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | RPA vs Physical Robotics — core difference? | RPA automates digital/software tasks via UI and application interaction (the 'digital robot'); physical robotics automates manipulation of physical objects. Exam tip: clicking/typing/reading screens → RPA; moving/lifting/sensing objects → physical robot. |
| 2 | Attended RPA bot — defining trait? | Runs on a user's desktop, triggered by a human during a live task (e.g., agent pulls customer data during a call). Front-office use case. Exam tip: attended = human-in-the-loop, on-demand trigger. |
| 3 | Unattended RPA bot — defining trait? | Runs on a server/VM without human presence, triggered by schedule or system event (e.g., nightly batch reconciliation). Back-office use case. Exam tip: unattended = no human trigger needed. |
| 4 | Intelligent automation = ? | RPA + AI/ML combined — e.g., OCR/NLP extracts data from unstructured documents, then RPA performs the repetitive digital task (data entry, routing). Exam tip: pure RPA cannot handle unstructured data alone. |
| 5 | What is RPA's biggest structural weakness? | Brittleness to UI changes — layout, button ID, or element changes can break bots relying on UI selectors. Exam tip: mitigated via governance, monitoring, and change management, not by adding more bots. |
| 6 | When should you choose RPA over a custom API integration? | When the target system has no accessible API and automation must happen through the UI (legacy apps, mainframes). Exam tip: if an API exists, API integration is generally preferred over RPA for stability. |
| 7 | When should you choose physical robotics over RPA? | When the task requires manipulating physical objects (picking, assembling, moving items) rather than digital data/UI. Exam tip: RPA never substitutes for physical manipulation tasks. |
| 8 | What does 'bot lifecycle management' typically include? | Design, development, testing, deployment, monitoring, maintenance, and decommissioning of bots — usually governed by a Center of Excellence (CoE). Exam tip: governance reduces risk from bot sprawl and UI brittleness. |
| 9 | RPA + AI for document processing is often called? | Intelligent Document Processing (IDP) — AI/ML (OCR, NLP, classification) extracts/interprets unstructured data; RPA automates the resulting workflow. Exam tip: 'unstructured documents' + 'data entry' scenario = IDP/intelligent automation answer. |
| 10 | Is RPA considered a form of physical robotics? | No. RPA bots are purely software — the 'digital robot' concept — and never interact with the physical world. Exam tip: a common wrong answer conflates RPA with physical cobots/robot arms. |
| 11 | What governance risk is specific to unattended bots using stored credentials? | Credential/security risk — unattended bots need stored service account credentials, requiring secure credential vaulting and access control as part of governance. Exam tip: hardcoding credentials in bot scripts is a common wrong-answer/bad-practice choice. |
| 12 | RPA scope — digital tasks it CAN automate? | Repetitive, rule-based, structured-data tasks across UI/applications: data entry, copy-paste between systems, form filling, report generation. Exam tip: RPA excels at structured, rule-based processes — not tasks needing judgment without AI augmentation. |
