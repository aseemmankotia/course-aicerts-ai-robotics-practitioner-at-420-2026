## Chapter 6: Generative AI for Robotic Creativity — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is synthetic training data generation used for in robotics? | Using generative models (diffusion models, GANs, simulators) to create large, varied labeled datasets without manual real-world capture, reducing cost and covering rare edge cases. Exam tip: pair with domain randomization for better sim-to-real transfer. |
| 2 | Foundation model in robotics — definition | A large model pretrained on broad, diverse data (vision, language, action) that can be fine-tuned as a reusable building block for many robot skills instead of training each skill from scratch. Exam tip: foundation model ≠ task-specific model. |
| 3 | Text-to-motion generation (conceptual) | Generates a robot trajectory/joint sequence from a natural language description of a desired action. Exam tip: output must still pass physical feasibility/safety checks before execution. |
| 4 | Generative hallucination in robotics — what's the risk? | A generative model produces a confident but physically unsafe, impossible, or incorrect action/plan. Exam tip: mitigate with constraint checking plus human-in-the-loop review. |
| 5 | Human-in-the-loop (HITL) review — when required? | Before deploying AI-generated robot designs, trajectories, or task plans to physical hardware, especially for safety-critical or novel outputs. Exam tip: HITL is the primary mitigation for hallucination risk. |
| 6 | Generative design for robot morphology | Uses generative/evolutionary AI to explore a large design space (limb shapes, actuator placement) for novel robot bodies optimized for task performance. Exam tip: targets physical structure, distinct from text-to-motion. |
| 7 | Diffusion models vs GANs for synthetic robot training data | Diffusion models: more stable training, higher fidelity, slower sampling. GANs: faster generation, prone to mode collapse. Exam tip: diffusion models are the current favored standard for high-quality synthetic data. |
| 8 | Domain randomization | Varying simulation parameters (lighting, textures, physics) during synthetic data generation to improve sim-to-real transfer robustness. Exam tip: often combined with generative models to expand variation further. |
| 9 | Vision-Language-Action (VLA) model | A foundation model type mapping visual input plus language instruction directly to robot action output; fine-tuned per robot/task. Exam tip: a key example of a foundation model used as a robot skill building block. |
| 10 | Why fine-tune instead of training from scratch? | Foundation models already encode broad visual/language/action priors; fine-tuning on a smaller task-specific dataset is faster, cheaper, and generalizes better than training from zero. Exam tip: core justification for foundation-model reuse. |
| 11 | Generative AI for creative task planning — key risk | LLM/generative planners may produce plausible-sounding but infeasible or unsafe multi-step plans when sequencing robot actions. Exam tip: validate generated plans against a world/physics model before execution. |
| 12 | Safety constraint checker in generative pipelines | A rule-based or learned module that filters/validates generative outputs (trajectories, plans, designs) against physical/safety limits before robot execution. Exam tip: required layer between generation and actuation to catch hallucinations. |
